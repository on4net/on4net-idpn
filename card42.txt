﻿## Plan

**Scope:** publishable `@idpn/mfe-sdk` workspace package, Web Component parity for the `account` module, and integration docs. No backend/API changes.

**Files / areas**
- `packages/mfe-sdk/` (new): `src/contract.ts` (IdpnMfeConfig, IdpnEvent union, module/mode/direction/theme types), `src/validate.ts` (boundary validation + token-key guard), `src/mount.ts` (`mountIdpnModule`, `unmountIdpnModule`), `src/version.ts` (SDK + contract version constants), `src/index.ts`, tests, tsconfigs, vitest config, README.
- `web/src/mfe/web-component.tsx`: one element class registered as `on4net-idpn-user-management` (unchanged default), `on4net-idpn-account` (new) and `on4net-idpn-mfe` (`module` attribute). `module` attribute/property; `theme` property.
- `web/src/mfe/{user-management,account}.tsx`: roots accept `theme` and pass it to `IdpnRoot` (needed for SDK theme tokens).
- `web/src/mfe/web-component.test.tsx`: account/module/theme tests.
- `docs/mfe-sdk.md` (new) linked from clean `docs/README.md`; root `package.json` `test:unit` includes the new package.
- Pre-existing modified docs are untouched; no hunks from them staged.

**Data model / API:** none. SDK types mirror `MFE_SCHEMA_VERSION` and are kept in sync by a contract-parity test against `@idpn/contracts` schemas.

**Security**
- SDK never writes a token into attributes, DOM text or events; SPA token getter is an in-memory JS property only and is cleared in `bff` mode.
- Config runtime guard rejects `accessToken`/`refreshToken`/`idToken`/`token`/`clientSecret`.
- `clientId`/`apiBaseUrl` come from host config only; no globals, no storage, no `postMessage`.
- Element still scopes all CSS in Shadow DOM; no host tokens leak.

**Compatibility**
- Legacy `<on4net-idpn-user-management>` keeps working with no `module` attribute.
- New tag `<on4net-idpn-account>`; generic `<on4net-idpn-mfe module="...">`.
- `Unmount` clears element callbacks and removes the node; re-mount creates a fresh React root.

**Tests**
- SDK unit (jsdom): attributes vs properties, no token leakage, bff clears getter, re-mount/update, module switch, unmount, invalid config, contract/version parity.
- Web: both modules through the Web Component element, `module` property, theme token, legacy element test still green.
- Builds: `@idpn/mfe-sdk` build; `@idpn/web` typecheck/test:coverage/build/build:wc/build:mfe; workspace typecheck; eslint + prettier on changed files; `contract:check`.

**Acceptance criteria verified in this card:** SDK package with Config/Event types; MF + WC outputs remain buildable; SemVer/manifest policy documented; React + Vue/HTML examples; contract/version test; docs linkable from `docs/README.md`. Sample-app consumption and CI workflow wiring are covered by #43/#44, so those boxes stay unticked here.

## Implementation report

Commit: `8a30012` on `a-main` (single commit, no push performed).
Scope: `@idpn/mfe-sdk`, Web Component account/module selection, integration docs. No API, schema or generated-contract changes. Pre-existing uncommitted modifications in `.github/*` and the other `docs/*` files were left untouched and unstaged.

### What changed

**New package `packages/mfe-sdk` (`@idpn/mfe-sdk@0.1.0`, no runtime dependencies)**
- `IdpnMfeConfig`, `IdpnEvent` (exactly the 7 documented events, no token fields), `IdpnMfeModule` (`user-management` | `account`), `IdpnMfeMode` (`bff` | `spa`), `IdpnDirection`, `IdpnThemeTokens`, `IdpnMfeElementProps`, `IdpnReactModuleProps`.
- `mountIdpnModule(container, config)` creates `<on4net-idpn-user-management>` / `<on4net-idpn-account>` with `client-id`, `api-base`, `locale`, `dir` attributes and in-memory `getAccessToken` / `onEvent` / `theme` properties; idempotent re-mount, `update()`, module switch, `unmount()` + `unmountIdpnModule()`.
- Runtime boundary validation rejects empty ids, unknown module/mode/dir and `accessToken` / `refreshToken` / `idToken` / `token` / `clientSecret` before touching the DOM. BFF mode clears any token getter.
- `IDPN_MFE_SDK_VERSION = 0.1.0`, `IDPN_MFE_CONTRACT_VERSION = 1`; package configured for `pnpm pack`/publish (`dist` + README only).
- Tests: mount/unmount attributes vs properties, no token in attributes/DOM/events, BFF clears getter, theme, update/re-mount/module switch, invalid configs, SSR guard, contract parity against `@idpn/contracts`, SemVer/package-version parity.

**Web Component (`web/src/mfe/web-component.tsx`)**
- One element class registered as `<on4net-idpn-user-management>` (legacy default), `<on4net-idpn-account>` (new) and `<on4net-idpn-mfe module="…">` (explicit).
- `module` attribute **and** property; property wins. Properties `theme`, `onEvent`, `getAccessToken` are accessors and re-render when set after mount.
- `dir` now falls back to the locale-derived direction when the attribute is absent (user-management keeps its `rtl` default).
- `UserManagementRoot` / `AccountRoot` accept `theme` and forward it to `IdpnRoot` as `--<name>` / `--idpn-<name>`.

**Docs**
- New `docs/mfe-sdk.md`: install, Module Federation + Web Component setups, config/attribute tables, event contract, BFF vs SPA security rules, CSP/headers, versioning/publishing, troubleshooting, complete React + vanilla HTML + Vue 3 examples.
- Linked from the clean `docs/README.md`; `packages/mfe-sdk/README.md` added.
- Root `test:unit` now includes `@idpn/mfe-sdk` (CI already runs `pnpm test:unit`).
