# RTL Audit — shadcn/ui components and IDPN surfaces

Scope: every vendored component in `web/src/components/ui`, the Hosted Auth UI (`web/src/app`),
the federated modules and Web Component bridge (`web/src/mfe`), and the standalone admin console
(`web/src/admin`). Standard: [`docs/design-system.md`](./design-system.md) §6.

Audited on 2026-10-19 (issue #55). Rule: logical utilities only
(`ps/pe`, `ms/me`, `start/end`, `text-start/text-end`, `rounded-s/e`); physical utilities are
allowed only when they are symmetric (`px-*`, `py-*`, `border`, `rounded-lg`, `gap-*`).
Machine-readable values (email, URL, code, JSON, IDs) are isolated with `<bdi>` or a
value-scoped `dir="ltr"`; `dir` is never used to fix the layout of a block.

## Findings

An automated scan (`web/src/components/ui/rtl.test.tsx`) rejects `text-left`, `text-right`,
`ml/mr`, `pl/pr`, `left/right`, `border-l/r`, `rounded-l/r`, `translate-x`, `space-x` and
`slide-in-from-left/right` in every rendered primitive. None were present in the shipped
components at the start of the audit; the remaining findings were direction semantics:

| Component / screen                                                  | Issue                                                                                                                                      | Fix                                                                                                               | Exception                                                                                                   |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `IdpnRoot`                                                          | Direction provider already wraps hosted UI and both MFE roots, but standalone admin had none                                               | Admin console now renders `Direction.Provider` with `directionOf(locale)`                                         | Portal targets still live inside `.idpn-root`                                                               |
| `Dialog`                                                            | `DialogContent` portals to `document.body` on standalone surfaces, leaving the `dir` subtree, so an RTL dialog rendered LTR                | `DialogContent` reads `Direction.useDirection()` and writes `dir` on the portalled overlay                        | None                                                                                                        |
| `Select`                                                            | Trigger/item text had no explicit logical alignment; decorative `▾` was readable by assistive tech                                         | `text-start` on trigger/content/item; indicator marked `aria-hidden`                                              | Down caret is vertically symmetric — no mirroring                                                           |
| `Input`                                                             | No explicit start alignment made it easy to rely on the physical default in reviews                                                        | `text-start` added                                                                                                | `type="email"`/code inputs keep a value-scoped `dir="ltr"`                                                  |
| `Alert`                                                             | Icon was positioned with logical `start-4`, but text had no logical inline padding, so text underlapped the icon                           | `[&>svg~*]:ps-7` plus explicit icon size                                                                          | None                                                                                                        |
| `Table`                                                             | Header used `text-start`; body cells and caption relied on inheritance                                                                     | `text-start` on table, cells and caption                                                                          | Numeric/date cells still use `Intl` formatting only                                                         |
| `Card`, `Badge`, `Button`, `Label`, `Tabs`, `ScrollArea`, `Spinner` | No direction-sensitive class; flex/gap/padding are symmetric                                                                               | No change                                                                                                         | `Spinner` default screen-reader label is Persian; tracked by the localization work, not an RTL layout issue |
| `LoginForm`                                                         | Accepted `dir` and discarded it (`void dir`), so the form was not self-contained outside `IdpnRoot`                                        | `dir` applied to `<main>`; identifier input uses `dir="auto"` for mixed username/email input                      | Password fields inherit the form direction                                                                  |
| `MfaForm`                                                           | `dir` was on the inner `<form>` only                                                                                                       | Moved to the card root                                                                                            | One-time code input stays `dir="ltr"` (value scope)                                                         |
| `account-flows`                                                     | Email input was already `dir="ltr"`; card relied on the root                                                                               | No structural change                                                                                              | Email input: `dir="ltr"` around the value only                                                              |
| `SocialLogin`                                                       | Provider buttons/labels and the `یا`/`or` divider are direction-neutral                                                                    | No change                                                                                                         | Provider brand names stay LTR                                                                               |
| `UserManagement`                                                    | `dir="ltr"` was set on the whole client-id paragraph and the email `<td>`, flipping block alignment; caption mixed an LTR id into RTL text | Values wrapped in `<bdi>` / `<bdi dir="ltr">`; table cells keep `text-start`; invite email/JSON inputs scoped LTR | JSON textarea uses `dir="ltr"` (machine-readable)                                                           |
| `Account`                                                           | Email, username, locale, session client id, IP and user agent were raw mixed-direction text                                                | `<bdi>` isolation; email `dir="ltr"`; `lang` added to the module root                                             | Dates come from `Intl.DateTimeFormat(locale)`                                                               |
| MFA/passkey section                                                 | Secrets, recovery codes and OTP inputs already scoped `dir="ltr"`                                                                          | No change                                                                                                         | `<ul dir="ltr">` for recovery codes                                                                         |
| Web Component bridge                                                | Configuration-error messages hard-coded `dir="rtl"` even for an `en-US`/`ltr` host                                                         | Direction derived from `dir` attribute or `directionOf(locale)`; `lang` set                                       | None                                                                                                        |
| Admin console                                                       | No `DirectionProvider`, no `dir` on the console root; email/username and temporary password were not isolated                              | Provider + `dir`/`lang`; `<bdi>` and value-scoped LTR code block; email input `dir="ltr"`                         | None                                                                                                        |
| Admin sessions view                                                 | `locale === 'fa-IR'` instead of `directionOf`; client id set `dir="ltr"` on the `<td>`; IP/UA raw                                          | `directionOf(locale)`; `<bdi>`; filter inputs keep value-scoped LTR                                               | Filter inputs are identifiers, so `dir="ltr"` is intentional                                                |
| Admin audit view                                                    | Action/actor/target/client values were raw mixed text                                                                                      | `<bdi>` around each machine-readable value; `dir`/`lang` on the card                                              | None                                                                                                        |
| Language switcher                                                   | Not implemented yet in this phase; locale arrives from `ui_locales` and public config                                                      | No change — recorded as N/A, not invented                                                                         | Tracked by the localization/context work                                                                    |
| Fonts                                                               | Per-direction stack is applied by `idpnThemeToCssVariables` (`Vazirmatn` RTL / `Inter` LTR) and covered by `idpn-root.test.tsx`            | No change                                                                                                         | Font files are loaded by the embedding host                                                                 |
